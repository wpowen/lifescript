# 天机录 · LifeScript-Solo 定制化设计方案

## 1. 目标

把 `LifeScript-Solo` 从“通用单本互动小说壳”推进到“可承载 1200 章长线修仙互动爽文”的状态，并针对《天机录》的核心卖点做定制化设计：

- 修仙升级的长期成长感
- 谋略型主角的“提前落子”爽感
- 天命值消耗与改命风险的策略感
- 人物关系从单一好感变成多维人心博弈
- 长篇连载下的阶段目标、卷段里程碑与追更动力

## 2. 当前项目现状

### 2.1 已有基础

`LifeScript-Solo` 已经具备单本书壳子的主要模块：

- 入口页：`Entry`
- 阅读页：`Reading`
- 人物档案：`Dossier`
- 路线图：`RouteMap`
- 章节结算：`Settlement`
- 单 SKU 配置：`project.yml + Info.plist`

它适合快速做“单本书独立 App”，这一点是正确方向。

### 2.2 《天机录》当前数据状态

项目目录里已存在《天机录》内容包：

- 目录：`LifeScript-Solo/天机录/if`
- 规划总章数：`1200`
- 当前已生成章节文件：`271`
- 当前选择节点数：`655`
- 平均每章节点数：`23.49`
- 平均每个选择点选项数：`2.47`

这说明《天机录》已经不是概念书，而是一个正在持续长线生产的数据项目。

## 3. 什么是“仙侠 / 修仙”在产品里的正确设计

修仙不是简单换皮成“有境界值的玄幻”，它的交互设计必须抓住下面几件事：

### 3.1 核心情绪契约

- 变强，而且每一层都更强
- 低位蛰伏，高位反杀
- 争资源、争传承、争站位、争天命
- 不是只赢一场，而是不断逼近更高规则层

### 3.2 修仙题材必须有的结构

- 明确的等级与门槛：炼气、筑基、金丹等，或者对应的阶段性成长替代物
- 资源稀缺：灵石、机缘、残页、秘境、法宝、师承
- 阵营结构：宗门、魔道、世家、皇朝、上古遗迹
- 人心结构：师承、道侣、宿敌、同门、长辈、器灵/残魂
- 代价结构：越接近真相，越高风险，越高反噬

### 3.3 《天机录》的题材抓手

《天机录》不是传统“热血硬刚修仙”，而是“预见未来 + 扮猪吃虎 + 因果布局”的谋略修仙。

所以它最该强化的不是：

- 单纯战力条
- 单纯升级爽点

而是：

- 何时动用天机录
- 何时示弱，何时摊牌
- 先稳哪条人物线
- 哪个真相要提前拿，哪个后手要留到下一卷
- “我早就算到了”这种智斗快感

## 4. 互动式游戏 / 互动小说应该怎么设计

### 4.1 互动不是“选结果”，而是“选推进方式”

好的互动小说，不应该让玩家频繁决定“赢还是输”，而应该让玩家决定：

- 怎么赢
- 先赢谁
- 用什么代价赢
- 这次是公开打脸，还是埋伏到下一章

这和本项目仓库里的研究结论是一致的：互动点应该落在“过程变量”上，而不是落在单薄的二选一结果上。

### 4.2 长篇互动小说的单章循环

单章更适合稳定复用下面这套循环：

1. 上章钩子兑现
2. 冲突升级
3. 关键互动
4. 即时反馈
5. 小高潮/小爽点
6. 下一章强钩子

### 4.3 玩家必须“看见自己的影响”

互动小说最怕两件事：

- 选了，但体感上没变化
- 变了，但玩家不知道哪里变了

所以反馈必须显性化：

- 角色态度变化要立刻提示
- 天命值/名望/谋略变化要立刻提示
- 关键阈值变化要立刻提示
- 章节结算要复盘“这章你做了什么，留下了什么”

## 5. 当前设计存在的问题

### 5.1 内容接入层有缺口

当前 `Solo` 壳默认读取：

- `book_xxx.json`
- `chapters_xxx.json`
- `walkthrough_xxx.json`

而《天机录》现在是：

- `story_package.json`
- `chapters/chXXXX.json`

也就是说，之前的壳子其实接不住《天机录》这种“生成中目录包”。

### 5.2 数据模型太刚性，不适合长篇生成内容

当前旧模型只支持固定爽点类型和固定关系维度。

但《天机录》实际数据里已经出现：

- 关系维度：`好奇 / 警惕 / 轻视 / 愤怒`
- 爽点类型：`谋略爽 / 嘴毒打脸 / 智取`

这意味着如果模型不做柔性兼容，后面 1200 章越生成越容易炸。

### 5.3 互动反馈还不够“显”

当前阅读页已经会插入内联通知节点，但还不够强：

- 玩家做出选择后，视线焦点仍然停留在正文区域
- 属性/关系变化缺少“浮到脸上”的即时奖励
- 《天机录》这种谋略修仙，特别需要 `苏青瑶·信任 +5`、`天命值 -5` 这种强提示

### 5.4 人物档案页还是偏通用

当前档案页默认展示：

- 信任
- 好感
- 敌意

但《天机录》的关系不是这么简单：

- 苏青瑶更像“警惕 -> 信任 -> 守护”
- 夜清更像“好奇 -> 共谋 -> 依赖”
- 凌渊更像“轻视 -> 警惕 -> 愤怒 / 敌意”

如果档案页只显示固定三条，会把这本书最好玩的“人心维度”砍掉。

### 5.5 路线图过度依赖手工 walkthrough

《天机录》的 `story_package` 已经有：

- 主线阶段
- side routes
- hidden routes
- milestone 章段范围

但旧壳只认手工 `walkthrough_xxx.json`，导致现有包体里的阶段信息没有被利用起来。

### 5.6 生成数据缺少自动校验

当前《天机录》已发现 `3` 个结构异常章节：

- `ch0131.json`
- `ch0177.json`
- `ch0264.json`

问题模式主要是：

- 选择数组里混入了正文节点
- 复合节点里同时带 `text/dialogue/choice`

这不是“内容不好看”的问题，而是“长线生产没有校验闸门”的问题。

## 6. 《天机录》的定制化产品设计

### 6.1 这本书的核心幻想

不是“我比别人更能打”。

而是：

- 我提前知道一步
- 我表面是废物，暗地里已经落子
- 我让别人以为自己赢了，其实他已经踩进我布好的局

所以《天机录》的 UI、反馈和系统命名都要围绕这套幻想服务。

### 6.2 推荐的系统重心

#### A. 天命值

- 是本书的核心策略资源，不是普通蓝条
- 每次预见都要让玩家有“值不值”的抉择
- 关键阈值要有高亮提示：
  - 天命值不足，某些路线关闭
  - 天命值跌破阈值，反噬风险上升

#### B. 人物态度维度

不要只做单一好感。

优先保留并展示：

- 信任
- 好感
- 敌意
- 敬畏
- 依赖
- 好奇
- 警惕
- 轻视
- 愤怒

其中“警惕 / 轻视 / 好奇”对《天机录》尤其关键，因为这本书的乐趣就在于“别人怎么看你”。

#### C. 卷段与命途图

1200 章长篇必须做阶段性感知。

推荐把 route map 设计成：

- 卷段里程碑
- 当前已生成进度
- 当前玩家所在主阶段
- 暗线条件提示

这样长线追更才不会只剩“继续下一章”。

### 6.3 阅读页的定制反馈

建议《天机录》阅读页优先强化这些反馈：

- 选择后 toast：
  - `苏青瑶 · 信任 +5`
  - `夜清 · 好奇 +10`
  - `天命值 -5`
- 关键代价标识：
  - `动用天机录`
  - `暴露风险提升`
  - `血脉觉醒推进`
- 卷段感：
  - 当前目标
  - 当前棋局
  - 当前命途阶段

### 6.4 章节结算页的定制化内容

《天机录》的章节结算不应只写“属性变化”，而应优先放大：

- 本章关键落子
- 人心偏转
- 天命消耗与回收
- 新解锁的暗线风险
- 下一章的因果回响

## 7. 本次建议开发方向

### 7.1 已优先落地的方向

- 让内容层识别 `story_package.json + chapters/` 目录包
- 让阅读模型兼容未知爽点类型和扩展关系维度
- 给阅读选择增加即时 toast 反馈
- 档案页改为展示“当前最强关系维度”，而不是写死三项
- 利用《天机录》的 milestone 自动生成 fallback walkthrough

### 7.2 下一阶段建议

- 增加“连载中”状态显示：已生成 `271 / 1200`
- 增加阶段性大爽点标记：每 `5` 章 / 每卷关键章提示
- 增加天命值阈值警报 UI
- 增加《天机录》专属人物态度页：把“警惕 / 轻视 / 好奇”做成显性条
- 在内容工厂加入结构校验，阻止坏章节进入 App

## 8. 结论

《天机录》不是把已有修仙皮肤换个标题就能跑好的书。

它要求壳子从三个层面升级：

- 数据层：从固定 schema 升级为“长篇生成可兼容”
- 反馈层：从内联结果升级为“即时可感知反馈”
- 产品层：从通用修仙互动小说升级为“谋略改命型修仙长篇”

如果这一层做对，《天机录》会非常适合成为 `LifeScript-Solo` 的代表性单书 SKU：

- 长线足够长
- 爽点足够清晰
- 关系系统天然适合做上瘾反馈
- 天命值系统天然适合做策略与付费想象空间
